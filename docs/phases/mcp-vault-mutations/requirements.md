# MCP Vault Mutations Requirements

Status: Step 1 preparation implemented; source mutations and MCP tools not implemented.

Implementation tracking (#54): step 1 adds portable request validation,
preparation and bounded previews only. No writable adapter or MCP mutation tool
is enabled. Steps 2–5 and their runtime/security acceptance checks remain open.

## Purpose

MCPからMarkdownノートの追加・更新・削除と、添付ファイルのアップロード・
差し替え・削除を行う。2026-11-02の対話で合意した仕様を記録する。
既存の検索・取得の責務、local-first、private-by-defaultを維持する。

詳細: [MCP・書き込み・整合性仕様](specifications/mutations.md)。

## Agreed decisions

| 項目         | 決定                                                                               |
| ------------ | ---------------------------------------------------------------------------------- |
| 対象         | ローカルfilesystemとCloudflare R2の両方。接続先だけを変更し、自動同期しない        |
| 再upload     | クラウド編集とローカルuploadの変更が衝突したら拒否。黙って上書きしない             |
| ノート       | Markdownの新規作成、全文置換、部分置換、完全削除                                   |
| 添付         | 既存取得ポリシーで許可された種類の追加、明示的な差し替え、完全削除。本文編集なし   |
| パス範囲     | vault全体の許可対象。既存の除外・source scopeを超えない                            |
| 有効化       | デフォルト無効。一括で追加・更新・削除を有効化。操作別スイッチなし                 |
| 適用モード   | 標準は変更案を提示してから適用。設定で直接適用を許可できる                         |
| 承認         | MCPクライアントの実行確認に委ねる。サーバー側の人間承認機構は設けない              |
| プレビュー   | ノートは差分、添付はパス・サイズ・追加/差し替え、削除は対象一覧                    |
| 既存ファイル | 作成は既存パスを拒否。添付の差し替えは明示指定が必要                               |
| 競合         | 更新・差し替え・削除は取得時の版を必須にする。不一致は拒否し、強制指定なし         |
| 部分置換     | リテラルと正規表現に対応。正規表現のキャプチャ参照を許可                           |
| 一致数       | 標準は1か所。複数は明示許可と想定一致数が必須。実数が違えば変更しない              |
| 複数置換     | 1ノート内では順番に適用。途中で失敗したらそのノート全体を変更しない                |
| 自動補正     | 日時・frontmatterなどを自動変更せず、指定された変更だけ行う                        |
| フォルダ     | 保存先の親フォルダがなければ自動作成。除外・境界検証を適用                         |
| 移動・改名   | 初版では非対応                                                                     |
| 一括操作     | 複数ファイルを扱い、ファイルごとに成否を返す。成功分は残す                         |
| 同じパス     | 一括操作内の重複パスは、変更開始前に全体を拒否                                     |
| 削除         | ゴミ箱・復元機能なし。被リンクがあっても削除し、検出した参照元を警告する           |
| リンク       | 自動修正しない。参照元検出は索引の鮮度に依存し、完全性は保証しない                 |
| 保存と索引   | 保存完了で操作成功。索引反映は非同期で、結果に反映待ちを示す                       |
| 削除完了     | 元ファイル削除と新規検索・取得からの除外で完了。内部派生データは後で掃除           |
| ノート取得   | 索引反映前でも保存済み最新版を返す。版と反映待ちを明示                             |
| チャンク取得 | 旧版に基づく取得は拒否。最新版ノート取得か再検索を案内                             |
| 通常の結果   | 本文を返さず、パス・成否・版・索引反映状態などを返す                               |
| 添付転送     | MCPにBase64で直接送信。専用アップロード経路は初版に追加しない                      |
| サイズ       | Markdown・添付とも1件標準5 MiB。設定で変更可能。更新後本文にも適用                 |
| 一括上限     | 標準20件・合計20 MiB。設定で変更可能。Base64変換前のバイト数で計算                 |
| 上限超過     | 変更開始前に全体を拒否                                                             |
| 再送         | 操作IDで重複適用を防ぐ。同じID・同じ内容は結果を再利用。違う内容は拒否             |
| 操作期限     | 発行日時を含む操作IDを使い、期限切れIDは再実行せず拒否                             |
| 履歴         | 操作ID・日時・パス・種別・成否・版などの情報のみ。本文・差分・添付データは残さない |
| 保持         | 履歴と重複防止情報は標準7日間。設定で変更可能                                      |
| HTTP認証     | 閲覧用と書き込み用のキーを分離。閲覧用では変更不可                                 |
| 信頼         | ノート内の指示を操作の根拠にしない旨をツール説明に明記。ユーザー依頼に基づく       |

## Scope and boundaries

- 1プロセス/デプロイにつき1 vault。MCP stdio、ローカルMCP HTTP、Workers MCP HTTPを対象とする。
- 「vault全体」は現在設定されている許可scope内を意味する。Cloudflareのincludeや外部保存の同意を拡張しない。
- pCloudは既存契約どおりread-only。filesystem/R2以外は書き込み非対応として拒否する。
- Markdownの拡張子・添付の許可判定は既存の各sourceの取得ポリシーを再利用する。
  例外的なguidance取得許可を新たな編集権限へ自動転用しない。
- ローカルへの変更を勝手にuploadせず、クラウドの変更を勝手にdownloadしない。
  Git syncの意味を変更せず、pushや競合の自動解決を追加しない。
- 検索・relatedから本文取得や変更、LLM呼び出しを暗黙に実行しない。
- クライアントの確認を無効にすれば人間の確認なしに適用され得る。
  変更案と適用の分離はサーバーが人間の承認を保証する仕組みではない。
- 完全削除はvault-agentから復元する機能がないことを意味する。
  プロバイダーのバックアップまで即時に物理消去したと約束しない。

## Architecture and dependencies

共通coreは操作検証、パス・対象ポリシー、置換、一致数、差分、版の意味、
結果スキーマ、索引更新用の差分準備を所有する。
filesystem/R2アダプターはI/O、永続化、排他・条件付き書き込み、復旧を所有する。
server/transportは認証・認可、要求量制限、MCPとの変換を所有する。
CLIは設定・引数・表示を扱い、編集ロジックを複製しない。
read-onlyな`VaultSource`へ汎用write/deleteを追加せず、別の書き込み能力として扱う。

- [#44](https://github.com/s-titanium-74/vault-agent/issues/44): ローカルread/admin分離と共通認可。
  HTTP書き込みを有効にする前の依存。今回のキー分離を同じ権限モデルに統合する。
- [incremental publication](https://github.com/s-titanium-74/vault-agent/blob/main/docs/phases/cloudflare-deployment/specifications/incremental-publication.md):
  索引更新を再利用。D1のtransactionをR2/Vectorizeまで拡大解釈しない。
- 既存のPhase 3 read-only仕様は既存ツールと書き込み無効時に引き続き適用。
  本機能を明示的に有効化した接続の追加ツールと、対象sourceの鮮度規則だけを拡張する。

## Delivery steps

1. 共通スキーマ・パス・版・置換・上限・previewと、syntheticな契約テスト。
2. filesystemで保存・削除・操作ID・復旧・索引更新・最新版取得を接続。
3. #44と連携してstdio/HTTP MCP、適用モード、設定、認可とクライアント説明を接続。
4. R2/D1で保存・削除・read抑止・復旧・upload競合検出を接続。
5. ローカル/Workersの共通回帰、隔離したsyntheticな実Cloudflare検証と撤去を記録。

各stepの途中状態は初版全体の受け入れ完了と区別する。
実装のmerge、issue closure、利用者環境へのdeployも別に扱う。

## Acceptance criteria

- [ ] デフォルト無効で既存のread-only操作が動作し、無効時の変更呼び出しは副作用なしで拒否される。
- [ ] filesystem/R2でノートと許可添付のcreate/update/replace/deleteが動作し、pCloudは変更しない。
- [ ] 初回作成の衝突、版の不一致、除外・隠し/生成パス、symlink/親置換、境界外を拒否する。
- [ ] 変更案と適用、直接適用の有効化、クライアント承認への依存を実クライアント相当で検証する。
- [ ] リテラル/正規表現/キャプチャ、複数一致の明示、一致数不一致、順次置換の全取り消しを検証する。
- [ ] 正規表現の処理予算超過を中断でき、無制限にCPUを占有しないことを両runtimeで検証する。
- [ ] UTF-8本文と未変更部分を保ち、frontmatterや日時を勝手に補正しない。
- [ ] 親フォルダを安全に自動作成し、移動・改名やリンク自動修正を行わない。
- [ ] 1件/合計/件数/更新後本文の制限、Base64不正、重複パスを変更前に検証する。
- [ ] 一括操作で成功分を残し、ノート内の複数置換は一体として扱う。失敗分だけ再試行できる。
- [ ] 同一IDの同時呼び出し・再送・異なる内容・期限切れ・再起動・応答消失で重複適用しない。
- [ ] 失敗/適用済み/判定待ちを区別し、障害中に実行結果を推測して再適用しない。
- [ ] readキーは変更できず、HTTP/MCPセッションの再利用でも認可を迂回できない。stdioも有効化が必要。
- [ ] 最新ノートと索引の版を区別し、新規ノートを索引反映前に明示取得でき、旧版chunkを拒否する。
- [ ] 削除完了後、新規のsearch/related/graph/取得等から削除内容を再露出しない。旧版索引やvectorも権限を復活させない。
- [ ] 書き込み直後の削除/更新、Cron・watch・index・uploadとの競合で古い公開版が内容を復活させない。
- [ ] 再uploadの共通祖先との差分を検証し、クラウド編集・削除を黙って上書きしない。baseline不明は衝突扱い。
- [ ] 操作履歴は標準7日で掃除され、本文等を残さない。監査期限後も必要な削除抑止状態は保持される。
- [ ] 通常結果・ログ・エラーは内容/秘密/絶対パスを含まない。変更差分は明示preview応答だけに含む。
- [ ] syntheticな隔離Worker/D1/R2でMCPの追加→取得→更新→削除、認可、再試行、反映遅延を実証し、資源/資格情報を撤去する。

## Implementation design gates

ユーザー合意済みの製品動作と、実装方式の未検証点を分離する。
詳細仕様のAPI名・JSON名は実装案であり、製品動作を変えず一貫して調整できる。
次は実装前に方式と根拠を追記し、保証できない場合は黙って弱めず仕様を再検討する。

- Node/Workersで同じ意味になり、計算量を制限できる正規表現エンジン・構文・flags。
- ローカルの外部エディターと競合する保存時の版チェック、symlink防止、crash復旧の保証範囲。
- R2削除・D1抑止・操作記録を跨ぐ復旧手順と、期限切れIDの検証/設定変更時の扱い。
- 変更案と同じ内容だけを適用するための拘束方法。監査履歴へ本文を保存しない実装。
- 既存の索引サイズ上限と新しい5 MiBの保存上限の整合。保存可能と全文索引可能を混同しない。
