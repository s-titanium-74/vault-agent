# vault-agent v0.2.5

## Changes

- Local index, watcher and reindex updates save each successful embedding batch
  to a durable cache. After a later batch times out or fails, retrying reuses
  completed inputs, including after a failed first build or full reindex.
- Local indexing sends at most eight chunks per embedding request. Required
  embedding failures preserve the previous published index; optional failures
  publish lexical changes and successful vectors together and leave other
  chunks pending for the next update.
- Health and status now agree on embedding readiness: all published chunks must
  have embeddings. Lexical freshness remains separate from embedding completion.
- Update diagnostics preserve safe error codes such as `EMBEDDING_TIMEOUT`
  without forwarding provider messages. Periodic failures are recorded in
  freshness state, and watcher logs use safe codes.

See [#87](https://github.com/s-titanium-74/vault-agent/issues/87) and
[#88](https://github.com/s-titanium-74/vault-agent/pull/88).
These recovery changes apply to the local SQLite runtime, including local
pCloud sources. Hosted Workers retain their existing update workflow.

## Installation

- Docker image `namka0703/vault-agent:0.2.5`.
- npm packages: `@vault-agent/cli@0.2.5`, `@vault-agent/core@0.2.5`, and
  `@vault-agent/server@0.2.5` are published.
- Local source builds require Node.js 22 or newer. Existing local configuration
  and indexes are reused; no full rebuild is required for this upgrade.

See the [local setup guide](https://github.com/s-titanium-74/vault-agent/blob/v0.2.5/docs/setup-guide.md)
and [Cloudflare setup guide](https://github.com/s-titanium-74/vault-agent/blob/v0.2.5/docs/cloudflare-setup-guide.md).
