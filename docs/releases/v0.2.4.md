# vault-agent v0.2.4

## Changes

- Guidance retrieval through HTTP and `vault_guidance_get` now returns a
  `version` corresponding to the returned source content. Use it as
  `expected_version` with the existing `patch_note` or `replace_note`,
  `preview_changes`, and `apply_changes` workflow. No new MCP tools are required.
- Existing visible Markdown guidance such as `AGENTS.md` can be safely updated
  within the configured write scope, including pCloud. Write enablement,
  READWRITE/ADMIN authorization, exclusions, review bindings, and version
  checks remain enforced. Hidden and non-Markdown guidance remain read-only;
  pCloud guidance creation and deletion remain unsupported.
- R2 guidance retrieval returns the saved source while indexing is pending,
  so clients can verify an applied update immediately. pCloud guidance updates
  remain outside the note search index and are not replicated to R2.

See [#84](https://github.com/s-titanium-74/vault-agent/issues/84) and
[#85](https://github.com/s-titanium-74/vault-agent/pull/85). The documented
filesystem final-check/save race and pCloud exclusive-writer limitations still
apply; R2 retains conditional writes.

## Installation

- Docker image `namka0703/vault-agent:0.2.4`.
- npm packages: `@vault-agent/cli@0.2.4`, `@vault-agent/core@0.2.4`, and
  `@vault-agent/server@0.2.4` are published.
- Local source builds require Node.js 22 or newer. Cloudflare Workers use a
  separate deployment.

See the [local setup guide](https://github.com/s-titanium-74/vault-agent/blob/v0.2.4/docs/setup-guide.md)
and [Cloudflare setup guide](https://github.com/s-titanium-74/vault-agent/blob/v0.2.4/docs/cloudflare-setup-guide.md).
