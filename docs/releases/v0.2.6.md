# vault-agent v0.2.6

## Changes

- Local embedding requests recover from recognized input-size errors by
  isolating oversized inputs, splitting them at Unicode character boundaries,
  and combining every part into one length-weighted, normalized vector.
- Note content, search chunks, chunk IDs and existing successful embedding
  caches are preserved. Pending inputs can recover on the next index update;
  no full reindex is required.
- Recovery has bounded split depth, attempt count and a shared request deadline.
  Unrelated HTTP errors are not retried. Terminal size errors retain the safe
  `EMBEDDING_INPUT_TOO_LARGE` code.

See [#90](https://github.com/s-titanium-74/vault-agent/issues/90) and
[#91](https://github.com/s-titanium-74/vault-agent/pull/91).
This applies to the local runtime, including local pCloud sources. Hosted
Workers retain their existing provider policy. Combined vectors approximate a
whole-input embedding; successful responses that silently truncate inputs
cannot be detected by this recovery mechanism.

## Installation

- Docker image: `namka0703/vault-agent:0.2.6`.
- npm packages: `@vault-agent/cli@0.2.6`, `@vault-agent/core@0.2.6` and
  `@vault-agent/server@0.2.6`.
- Node.js 22 or newer is required for local source and npm installations.
  Existing configuration and indexes are reused.

See the [local setup guide](https://github.com/s-titanium-74/vault-agent/blob/v0.2.6/docs/setup-guide.md)
and [Cloudflare setup guide](https://github.com/s-titanium-74/vault-agent/blob/v0.2.6/docs/cloudflare-setup-guide.md).
