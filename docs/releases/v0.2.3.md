# vault-agent v0.2.3

## Changes

- Read pCloud guidance files such as `AGENTS.md` and inspect or download
  supported attachments through HTTP and MCP on local servers and Cloudflare
  Workers. Guidance lists and attachment metadata contain no file bodies.
  These reads use the configured pCloud scope and leave the originals in
  pCloud. See [#82](https://github.com/s-titanium-74/vault-agent/pull/82).
- Create, replace and delete pCloud attachments through MCP when writes are
  enabled and the caller has write access. To replace or delete an attachment,
  use the version returned by an explicit download. The configured review or
  direct mode and pCloud's exclusive-writer requirement apply. See
  [#82](https://github.com/s-titanium-74/vault-agent/pull/82).
- Make MCP change previews and status lookups read-only. Preview returns a signed
  operation ID, and the first valid apply records it before changing files.
  Clients can use the read-only annotations when deciding when to ask for
  confirmation. See [#80](https://github.com/s-titanium-74/vault-agent/pull/80).

## Installation

- Docker image `namka0703/vault-agent:0.2.3`.
- The npm workspaces are versioned at 0.2.3. Publication of
  `@vault-agent/cli`, `@vault-agent/core`, and `@vault-agent/server` to the npm
  registry is pending registry authentication.
- Local source builds require Node.js 22 or newer. Cloudflare Workers use a
  separate deployment.

See the [local setup guide](https://github.com/s-titanium-74/vault-agent/blob/v0.2.3/docs/setup-guide.md)
and [Cloudflare setup guide](https://github.com/s-titanium-74/vault-agent/blob/v0.2.3/docs/cloudflare-setup-guide.md).
