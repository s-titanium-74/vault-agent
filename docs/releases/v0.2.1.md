# vault-agent v0.2.1

vault-agent 0.2.1 adds explicitly enabled, reviewed MCP editing for pCloud-backed
Markdown notes and reduces downloads during pCloud reconciliation. Filesystem
and R2 behavior retain their existing defaults; pCloud access and all writes
remain opt-in.

## Changes

- Create, replace, patch, and permanently delete scoped pCloud Markdown notes
  through `preview_changes`, `apply_changes`, and `get_change_status` in local
  Node and Cloudflare Workers runtimes. pCloud writes require review mode;
  direct mode, attachments, and rename operations are unsupported.
- Check the current content revision before writing and verify the resulting
  state afterward. Ambiguous provider outcomes enter reconciliation without
  automatically replaying the write; reuse the operation ID to inspect status.
- Reconcile confirmed changes into SQLite or D1 asynchronously. Explicit note
  reads can return saved content while indexing is pending, and stale chunk
  references are rejected.
- Download bodies only for new or changed notes during ordinary pCloud
  reconciliation, using complete provider metadata observations. Existing local
  indexes without these observations read the scoped notes once to establish
  them. Full reindexing and explicit revision-checked reads still verify bytes.
- Raise the local pCloud note-count ceiling from 500 to 10,000. Workers retain a
  500-note ceiling. Recursive listings remain bounded to 10,000 entries and
  4 MiB, including folder metadata, so the effective note count can be lower.
  The per-note limit remains 2 MiB.
- Add step-by-step pCloud setup instructions for local servers and Workers,
  including credentials, source scope, polling, and reviewed writes.

## Setup and compatibility

For an already configured pCloud source, enable writes in user-local settings:

```bash
vault-agent config set write.enabled true
vault-agent config set write.mode review
```

Supply `VAULT_AGENT_PCLOUD_ACCESS_TOKEN` through the process environment with
the required provider permissions. Local HTTP mutation clients still require
distinct read/admin credentials; stdio uses the local process trust boundary.
On Workers, explicitly enable `WRITE_ENABLED`, use `WRITE_MODE=review`, and keep
ingestion/Cron enabled. See the
[local setup guide](https://github.com/s-titanium-74/vault-agent/blob/v0.2.1/docs/setup-guide.md)
and [Cloudflare setup guide](https://github.com/s-titanium-74/vault-agent/blob/v0.2.1/docs/cloudflare-setup-guide.md).

pCloud does not provide an atomic expected-revision condition for the upload
and delete operations used here. An external edit can occur between the final
revision check and the provider write. Use one vault-agent writer per configured
scope and disable other writers, including pCloud Sync and web editing, for that
scope. Read-back verification cannot prove that an intervening edit was
preserved. Deletion is permanent and has no trash or automatic link repair.

Ordinary reconciliation now trusts provider metadata to identify unchanged
notes. If bytes change without a provider metadata change, an explicit
revision-checked note read or full reindex detects the mismatch. This release
does not claim continuous byte verification during every poll.

## Packages and images

- npm versions: `@vault-agent/cli@0.2.1`, `@vault-agent/core@0.2.1`, and

- Requires Node.js 22 or newer for local npm/source use. Cloudflare remains a
  separate installation and deployment.

## Validation limits

pCloud tests use synthetic provider responses for scope, revisions, ambiguous
writes, and index convergence. They do not establish real-account permissions,
provider concurrency behavior, or deployed pCloud write performance.
